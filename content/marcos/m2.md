## Loop M2

> **TodoWrite:** ao iniciar M2 e após cada rodada/bloco concluído, atualizar `TodoWrite` conforme MAPA DE PROGRESSO em `content/orchestrator.md` (Etapa 2). Semear rodadas conforme são iniciadas (não todas de uma vez). Marcar `completed` ao encerrar cada bloco; loop-back: reverter apenas o item afetado para `in_progress`. Nunca expor nome de skill, marco ou gate.

O orquestrador executa blocos alternados, respeitando a ordem fixa de `agenda_m2.topicos_pendentes`: [entrevista, cenarios, dominio, implicitos, feixe].

### Bloco COLLECTOR — Rodada N (tópico = agenda_m2.topico_atual)

Adotar persona collector. Usar skill da rodada conforme mapeamento:
- Rodada 1 (entrevista): Use skill `entrevista-estruturada` agora.
- Rodada 2 (cenarios): Use skill `cenario-narrativa` agora.
- Rodada 3 (dominio): Use skill `recomendacao-dominio` agora.
- Rodada 4 (implicitos): Use skill `recomendacao-implicitos` agora.
- Rodada 5 (feixe — condicional): Use skill `questionario-feixe` agora SOMENTE se ≥ 3 áreas sem cobertura após as rodadas 1–4 (ver workflow [A5]); senão, marcar o tópico como concluído sem executar.

Salvar respostas em `documentos-tecnicos/02-requisitos/02-elicitacao-raw.md` seção "Rodada N — \<tópico\>". Marcar `agenda_m2.topico_atual` como concluído.

### Bloco MODELER — após cada Rodada

Adotar persona modeler. Executar em ordem:
1. Use skill `classificacao-rf-rnf` agora.
2. Use skill `priorizacao` agora.
3. Use skill `glossario` agora.
4. Use skill `conflitos-detect` agora.
5. Atualizar `documentos-tecnicos/02-requisitos/02.1-requisitos-funcionais.md`, `documentos-tecnicos/02-requisitos/02.2-requisitos-qualidade.md`, `documentos-tecnicos/02-requisitos/02.3-restricoes.md`. Se premissas detectadas: criar/atualizar `documentos-tecnicos/02-requisitos/02.4-premissas.md`.
6. Use skill `pautas-reelicitacao` agora. Registrar lacunas com formato `(skill-alvo: <nome>)`.

### Fechamento — após 5 rodadas (ou após Fase B resolver pendências)

Adotar persona collector (1 última vez):
1. Use skill `traducao-leigo` agora.
2. Use skill `traducao-gate` agora → produz par `-leigo` para cada artefato de gate (02.1, 02.2, 02.3).
3. Executar C4.4 + C4.5; só então abrir Gate 2.

Parada: loop encerra SOMENTE quando `pautas-reelicitacao.md` não tem itens `[ ]` (convergência) — itens abertos bloqueiam o Gate 2. A partir da 3ª rodada com itens abertos, oferecer ao usuário continuar agora ou pausar e retomar depois (nunca "seguir assim") — ver `content/constitution.md` §POLÍTICA DE GATES.

## Auto-checagem ao final de cada turno (C4.4)

ANTES DE FINALIZAR O TURNO, verificar:
1. Foi escrita prosa para o usuário neste turno? Se sim → REFAZER como `AskUserQuestion`. Não publicar prosa.
2. Foi gerado algum arquivo neste turno? Verificar nome contra tabela canônica M2 acima.
3. Se nome inválido (ex: `srs.md`, `SRS-completo.md`, `requisitos.md`, `fluxos.md`) → NÃO criar.
4. O collector executou mais de uma rodada neste turno? Se sim → violação do HARD-GATE; registrar.
5. Se violação detectada → registrar em `estado-projeto.yaml.violacoes_detectadas[]` com timestamp + tipo.

Antes do PRE-FLIGHT do Gate 2, listar o diretório do projeto e cruzar com a tabela canônica de M2:

1. `ls <pasta-projeto>/documentos-tecnicos/02-requisitos/` e `ls <pasta-projeto>/documentos-para-leigo/02-requisitos/` → conjunto de arquivos presentes.
2. Para cada artefato OBRIGATÓRIO (Gate = Gate 2 e Tipo ≠ Condicional) da tabela canônica de M2:
   - `documentos-tecnicos/02-requisitos/02-elicitacao-raw.md`, `documentos-tecnicos/02-requisitos/02.1-requisitos-funcionais.md`, `documentos-para-leigo/02-requisitos/02.1-requisitos-funcionais.md`, `documentos-tecnicos/02-requisitos/02.2-requisitos-qualidade.md`, `documentos-para-leigo/02-requisitos/02.2-requisitos-qualidade.md`, `documentos-tecnicos/02-requisitos/02.3-restricoes.md`, `documentos-para-leigo/02-requisitos/02.3-restricoes.md`, `documentos-tecnicos/02-requisitos/02.5-glossario.md`, `documentos-tecnicos/02-requisitos/02.6-pautas-reelicitacao.md`
   - Se ausente → `_pendencias.md`: `C4.5-MISSING: <arquivo>` + BLOQUEAR gate.
3. Artefatos CONDICIONAIS (`documentos-tecnicos/02-requisitos/02.4-premissas.md`, `documentos-tecnicos/02-requisitos/02.7-conflitos-detectados.md`) NÃO disparam violação se ausentes.
4. Se qualquer C4.5-MISSING registrado → NÃO executar PRE-FLIGHT; RE-INVOCAR collector ⇄ modeler.

C4.5 complementa o PRE-FLIGHT — PRE-FLIGHT verifica conteúdo; C4.5 varre o diretório exaustivamente contra a tabela.
